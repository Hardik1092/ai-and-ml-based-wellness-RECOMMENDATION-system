# CEP Project — Synthetic Data and ML/LLM Comparison Plan

## Dataset generated for this iteration

- Target size: 20,000 synthetic wellness profiles.
- Seed: `42` for reproducibility.
- Target label: `wellness_category` (the existing six-category classifier target).
- Files generated by `ai-ml/app/training/export_dataset.py`:
  - `ai-ml/data/cep_synthetic_wellness_20000.csv`: raw generated profile fields plus target label.
  - `ai-ml/data/cep_ml_features_20000.csv`: the exact 14 engineered feature columns used by the current Random Forest model plus target label.
  - `ai-ml/data/cep_synthetic_wellness_20000.metadata.json`: schema, class counts, seed, and limitations.

## Training

From the `ai-ml` directory, with the project's Python dependencies installed:

```bash
python -m app.training.export_dataset --samples 20000 --seed 42
python -m app.training.train
```

Training defaults now use 20,000 generated rows. API `/train`, `/evaluate`, and `/retrain` request defaults are also 20,000. A caller can still explicitly pass another sample count.

## ML vs LLM: compare honestly

The current ML model predicts one focus category. The LLM produces structured narrative recommendations for nutrition, activity, and wellness. These are different output types, so do not compare them using a single accuracy score unless both outputs are mapped to the same independently reviewed target.

Recommended benchmark:

1. Freeze a reproducible holdout of 200 profiles that is not used for model training or prompt tuning.
2. Run ML and LLM on the same profiles and store input ID, outputs, elapsed time, failure status, and model/provider version.
3. Have a reviewer score each output using a fixed rubric: relevance to profile (0–2), actionable specificity (0–2), consistency with stated goal (0–2), explanation quality (0–2), and safety/constraint adherence (pass/fail).
4. Report ML classification metrics against the synthetic rule labels separately from the human-rated LLM/ML usefulness rubric. Report latency and failure rate for both.
5. Test allergy, dietary preference, activity-limit, and medical-safety constraints explicitly. Hard safety rules must override both model outputs.
6. If the goal is to claim real-world usefulness, repeat evaluation with appropriately consented, de-identified, real-world data and qualified review. Synthetic labels alone cannot support that claim.

## Limitations

The generated rows are synthetic and labels are assigned by the existing `label_row()` rules with configured label noise. This makes the dataset useful for development and repeatable pipeline testing, but it does not establish clinical validity or real-world accuracy. Do not use it to diagnose, prescribe, or make medical decisions.
